# Handoff: Host Run-Mode Choice + Go-Live Flow

## Overview
This redesign replaces the buried "Play along" checkbox in Queen Trivia's host flow
with an explicit **run-mode choice screen** shown right after a host finishes building
a game, and adds two supporting pieces so the flow is coherent end to end:

1. **Run-mode choice** — "How do you want to run this game?" with two equal, tappable
   cards: **Host only** and **Host & play**.
2. **Choose join code** — a dedicated step where the host sets a custom player join code
   (moved out of the old busy confirm screen; the code is NOT shown anywhere earlier in
   the build flow).
3. **Ready to go live** — a clean final confirmation with one consistent title and button
   label across web and mobile.
4. **Live-screen reassurance banner** — a dismissible, first-run-only banner shown on the
   live control screen **only when "Host & play" was chosen**.

The flow order is: **build game → run-mode choice → choose join code → ready to go live → live control screen**.

Applies to BOTH the React web app and the React Native / Expo mobile app. Wording and
layout must match across the two platforms.

## About the Design Files
The files in this bundle are **design references created in HTML** — a single Design
Component (`Run mode choice.dc.html`) that renders every screen in both a mobile phone
frame and a web/desktop frame. They are prototypes showing intended look, copy, and
layout — **not production code to copy directly**.

Your task is to **recreate these designs in the existing codebases** using their
established patterns:
- **Web**: React, using the app's existing components, styling approach, and routing.
- **Mobile**: React Native / Expo, using the app's existing components and navigation.

Match the visual style, colors, and playful tone of the current host screens. This is a
targeted redesign of a few steps, not a new look.

## Fidelity
**High-fidelity.** Colors, typography intent, spacing, copy, and interaction states are
final. Recreate the UI faithfully using each codebase's existing component library. The
exact hex values, sizes, and copy below are authoritative. (The HTML uses a phone/desktop
chrome wrapper purely for presentation — do not recreate the status bar, sidebar chrome,
or device bezel; reuse whatever the app already has.)

## Interactions & Behavior
- **Run-mode choice:** tapping a card selects it (single-select). No default selection.
  `Continue` disabled until a selection exists; on Continue → Choose join code.
- **Choose join code:** validate `6–12` chars, letters/numbers only, no spaces; uppercase
  as entered. `Continue` → Ready to go live. (Web has a copy button; the mobile step edits
  in place.)
- **Ready to go live:** `Edit` → back to Choose join code; `Change` → back to run-mode
  choice; `Review questions` → question list; `Go Live` → starts the game / live screen.
- **Live banner:** dismiss on "×"; persist dismissal (e.g. per-game or per-host flag) so it
  never shows again. Only rendered when mode === Host & play.
- No animations are required beyond the app's existing button hover/press states. Button
  hover on web: magenta `#f5138c` → `#ff2a9c`; outline buttons brighten border to `#445067`.

## State Management
- `runMode`: `'host_only' | 'host_and_play'` — set on the choice screen, read by the confirm
  screen (mode summary) and the live screen (whether to show the banner and the host's own
  answer UI).
- `joinCode`: string — set on Choose join code, shown read-only on Ready to go live, and on
  the live screen.
- `liveBannerDismissed`: boolean (persisted) — controls first-run banner visibility.
- Replaces the old `playAlong` checkbox state that sat next to the Go Live button.
